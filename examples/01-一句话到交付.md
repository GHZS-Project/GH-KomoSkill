# 实例：从「做个小工具」到「五点汇报」

> 这是一个完整对话的复盘，展示装上本技能后一次交付的样子。
> 目的：让你在 3 分钟内判断「这东西到底怎么用、值不值得装」。

---

## 起点（用户只说了 6 个字）

```
我：做个本地记账小网页
```

---

## S0 进场判断（不占用你的确认）

内部完成三项判断，不输出：

| 维度 | 判定 | 影响 |
|---|---|---|
| 类型 | 新建 | 需要初始化项目状态 |
| 风险 | 中 | 会写新文件，但都在新目录内 |
| 步数 | 4 步 | >3 步，必须走 S3 计划 |

---

## S1 需求补全（一次只问一个）

```
它：这个记账网页主要是自己用，还是要给家里人一起用？
你：自己用。
```

（4 要素里已有 2 个，继续问下一个）

```
它：数据存哪里？本地浏览器存储（换浏览器就没了），还是存个本地文件？
你：浏览器存储就行。
```

```
它：需要「当月合计」和「分类小计」这类统计吗，还是只要一个流水列表？
你：要当月合计，分类不用。
```

```
它：放哪个目录？默认我建在 ~/projects/ledger。
你：你在默认路径下建就行。
```

**然后它出需求确认单**：

```markdown
## 需求确认单
- 项目名：ledger
- 场景用途：个人记录日常收支，随时看当月花了多少
- 交付产物：单文件网页 ~/projects/ledger/index.html
- 核心功能：① 新增/删除账目（最不能少）② 当月合计 ③ 刷新不丢
- 约束偏好：纯前端，localStorage，不引 UI 框架，不联网
- 明确不做的：多账本、分类统计、导入导出、多用户
- 待核验：无
→ 以上是否正确？确认后进入启动确认。
```

```
你：确认
```

---

## S2 启动确认（⛔ 这一阶段它不建任何文件）

```markdown
## 启动确认清单
| # | 项 | 内容 |
|---|---|---|
| 1 | 项目类型 | 网页（单文件） |
| 2 | 项目目标 | 本地记账，当月合计可见 |
| 3 | 预计技术栈 | 原生 HTML + CSS + JS，无依赖 |
| 4 | 建议调用能力 | 无（单文件够用，不引技能） |
| 5 | 是否包含前端 | 是（单页，含基础样式） |
| 6 | 默认项目目录 | ~/projects/ledger |
| 7 | 主要交付内容 | index.html（内联 CSS/JS） |
| 8 | 预计验证方式 | 手动点 3 次：新增 / 刷新 / 删除 |
→ 是否按此方案开始？（本阶段不建任何文件）
```

```
你：确认
```

---

## S3 执行计划（≤5 步，每步可独立验证）

```markdown
## 执行计划
| 步 | 做什么 | 动什么 | 怎么验 | 风险 |
|---|---|---|---|---|
| 1 | 建目录 + 骨架页 | ~/projects/ledger/index.html | 浏览器能打开，标题正确 | 低 |
| 2 | 加表单 + 列表渲染 | 同文件 | 输入一条，列表出现该条 | 低 |
| 3 | 接 localStorage | 同文件 | 刷新后数据仍在 | 低（清缓存会丢） |
| 4 | 加当月合计 + 删除 | 同文件 | 加 3 条，合计=3 条金额之和；删 1 条合计随之变 | 低 |

→ 确认后开始执行。
```

```
你：确认
```

```
它：第 1 步 —— 建目录和骨架。
   产物：~/projects/ledger/index.html（42 行）
   小结：页面能打开，含标题与空列表容器。

它：第 2 步 —— 表单与渲染。
   产物：同上文件（118 行）
   小结：输入金额+备注→点添加→列表新增一行；未做持久化，刷新即丢（下一步修）。

它：第 3 步 —— 接 localStorage。
   产物：同上文件（151 行）
   小结：数据存 key `ledger.entries`；刷新后 3 条仍在（已实测）。

它：第 4 步 —— 合计与删除。
   产物：同上文件（196 行）
   小结：合计随增删实时变化；空列表时合计显示 ¥0.00。
```

## S5 验收交付（含自我反证）

```markdown
## 交付验收单
| # | 项 | 内容 |
|---|---|---|
| 1 | 交付物清单 | ~/projects/ledger/index.html（196 行，单文件） |
| 2 | 功能验证 | 新增 3 条（12.5 / 30 / 7.5）→ 合计显示 ¥50.00；刷新后仍在；删 30 → 合计 ¥20.00 |
| 3 | 自我反证 | 反证 A：删除 `` 后刷新，确认不会崩（实测：显示空列表 + ¥0.00）。反证 B：输入非数字时，确认被拦截（实测：输入 abc，提示「请输入数字」，不入库）。若这两项任何一项失败，说明 DOM 与存储层没对齐。 |
| 4 | 已知限制 | 清浏览器缓存会丢数据；无导出；金额不支持小数超过两位 |
| 5 | 后续建议 | 需要备份的话，下一步加「导出 JSON」按钮（约 20 行） |
→ 是否验收通过？
```

你：通过

---

## 复盘：哪一步最关键

| 环节 | 少了它会怎样 |
|---|---|
| S1 的四要素 | 做完才发现「要多人用」，得重做存储层 |
| S2 的「禁止落盘」 | 边问边建文件，需求一变就留下一堆垃圾文件 |
| S3 的验收列 | 到 S5 才发现「怎么算做完」根本没定义 |
| S5 的自我反证 | 只测了 happy path，输入非数字时直接崩 |
| S6 的实测数字 | 报「已完成」但没人知道到底验没验 |

## 反向对照：没有这套流程时

```
你：做个本地记账小网页
它：（直接开始写代码）
它：做好了！功能很完整，你可以试试。
你：（打开，输入一条，刷新，数据没了）
你：数据怎么没了？
它：哦，我忘了加持久化，我加一下。
```

**差别不在能力，在于「什么时候确认」和「凭什么说做完了」。**
