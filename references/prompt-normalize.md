# Prompt 规范化（S1 的核心动作）

> 用户给的是**口语**，不是需求。这一步把它翻成**可判定**的结构化 Prompt，再往下走。
> 判据：写完这份 Prompt，任何一个合格的执行者都能独立做出来，且能自己判断成败。

---

## 一、六字段模板

```markdown
【目标】一句话，且可判定成败
【输入】文件绝对路径 / 数据来源 / 现有代码位置
【边界】不许动的东西：其他项目、既有样式基线、数据库结构、.env …
【产出物】文件名 + 格式 + 落盘目录（绝对路径）
【验收】怎么算成功：可执行命令 / 可核对的数字 / 可视检查项
【失败】什么情况算失败：需要回滚还是重来
【待核验】当前拿不准、必须查证才能定的点（不许猜）
```

> 七行，不是六行 —— 最后一行 `待核验` 是**防幻觉的锚**：把不确定显式摆出来，避免它被偷偷当成事实写进方案。

## 二、优化四招

### 第 1 招：形容词 → 指标

| 口语 | 问题 | 改成 |
|---|---|---|
| 「弄好看点」 | 不可判定 | 「卡片间距 16px，圆角 12px，主色沿用现有 token」 |
| 「快一点」 | 不可判定 | 「首屏 < 1.5s，列表 1000 行滚动不掉帧」 |
| 「优化一下」 | 不可判定 | 「把重复的 3 处 fetch 合并成 1 个，减少 2 次请求」 |
| 「整理下」 | 不可判定 | 「按目录归并到 5 个分类，删除空目录」 |

**规则**：凡出现「好/快/清楚/合理/优化/整理」这类词，必须换成**数字或可观察的状态**。

### 第 2 招：补隐含约束

用户不会说的，但一定存在的边界：

- 不许动**其他项目**（范围铁律）
- 不许动**既有样式基线**（改版时最容易越界）
- 不许改**数据库结构**（除非明确说）
- 不许读 `.env` / 密钥
- 不许自动推远端
- 不许删用户数据（要删必须先列清单 + 确认）

### 第 3 招：补缺口但只问一个合并问题

发现缺 3 项信息时，**不要分 3 轮问**，压成一个问题：

> 「还差三点：① 放哪个目录 ② 要不要打包成 exe ③ 数据存本地还是云端。你定一下，或说『你定』我就按默认走。」

### 第 4 招：标不确定项

拿不准的地方，写进 `【待核验】`，**不许猜着往下做**。

例：
```
【待核验】目标站点是否需要登录才能看到列表页（影响是否要带 cookie）
【待核验】Node 版本是否 >= 20（`node:sqlite` 需要）
```

## 三、反例库（写出来一定会返工的）

| 反例 | 为什么不行 | 正确写法 |
|---|---|---|
| 「做一个数据看板」 | 没有数据源、没有指标、没有受众 | 「读 `data/sales.csv`，做 4 个 KPI 卡 + 1 个趋势图，单页 HTML，无后端」 |
| 「参考这个页面改一下」 | 「参考」可以是抄布局、抄配色、抄交互，三种结果差异极大 | 「沿用该页的**配色与卡片圆角**，布局按我们的三列来」 |
| 「把所有问题都修了」 | 范围不可控 | 「修这 3 条：① 登录报错 ② 列表分页错位 ③ 导出乱码」 |
| 「随便找个库实现」 | 引入不可控依赖 | 「优先用标准库；必须引依赖时先报名字和体积」 |
| 「先跑起来再说」 | 跳过验收标准 | 「先跑最小可用版：能读到数据并打印前 5 行即算通过」 |

## 四、口语 → 结构化 的两个实例

### 实例 1

**用户原话**：
> 帮我做个记账的小网页

**规范化后**：
```
【目标】单页本地记账网页，可增删改查账目并看到当月合计
【输入】无外部数据；首次打开为空，数据存浏览器 localStorage
【边界】纯前端，不接后端、不联网、不引 UI 框架
【产出物】<项目目录>/index.html（内联 CSS/JS，单文件）
【验收】浏览器打开可新增 3 条账目，刷新后仍在，当月合计数字正确
【失败】刷新后数据丢失 / 合计算错 = 失败，需重做存储层
【待核验】是否需要多账本（默认单账本）
```

### 实例 2

**用户原话**：
> 这个项目太乱了，整理下

**规范化后**：
```
【目标】把项目根目录从 23 项收敛到 ≤10 项，文档类归入 docs/
【输入】<项目目录>（先列全量文件树，不猜）
【边界】不改任何代码内容；不改 .git；不动 node_modules；不删无把握的文件
【产出物】整理后的目录结构 + 一份《移动对照表》（旧路径 → 新路径）
【验收】① 根目录条目数 ≤10 ② 所有文件仍可被 grep 到（无丢失）③ 移动对照表逐条可核对
【失败】出现任何文件丢失 = 失败，从备份恢复
【待核验】是否有脚本硬编码了旧路径（需先 grep 一遍）
```

## 五、输出格式（给用户看的样子）

不要直接把七字段甩给用户 —— 太长。用**两段式**：

```markdown
我的理解：
- 要做的：<一句话>
- 产出：<文件 + 目录>
- 不算成功的：<最容易被误解的那一条>

待你确认两点：① … ② …
```

用户回「确认」后，七字段存进 `PLAN.md`，不用再展示。

---

## 六、什么时候算规范化完成

三条都满足才算：

1. **可判定**：每一条都能用「是/否」验证，不含形容词。
2. **可复现**：换个人按这份 Prompt 做，产出应该基本一致。
3. **有锚点**：`待核验` 里的每一条都有明确的查证方式，不是「再看看」。

> 一句话检验：**如果做完之后你和用户会为「这算不算做完了」吵起来，说明这份 Prompt 没写好。**
