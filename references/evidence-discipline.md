# 证据纪律（防幻想）

> 这是本技能最有价值的一条：**没有证据就不许说完成**。
> 幻觉不是模型「不老实」，多半是三个缺口：地图错、证据缺、标准软。本文件逐条堵。

---

## 一、三态标注（强制）

任何判断必须落在三态之一，**不许混写**：

| 态 | 定义 | 表达方式 |
|---|---|---|
| **事实** | 有工具输出 / 文件内容 / 命令结果为证 | 「实测 `<命令>` 返回 X」 |
| **推断** | 有依据的猜，依据要说出来 | 「推断：可能因为 A，依据是 B」 |
| **待核验** | 必须查，不查不许往下做 | 「待核验：需先跑 X 确认」 |

**禁止句式**：
- ❌「应该已经好了」→ 要么去验，要么说「未验证」
- ❌「我记得是 8123 端口」→ 重新读配置
- ❌「一般来说这个库支持」→ 查文档或跑一次

---

## 二、五条硬动作

### 1. 改完回读

改文件后**必须重新读一次**再宣称改好。不看就报完成 = 纯幻想。

```bash
# 改完立刻回读关键行 + 校验结构合法性
grep -n "关键字段" <file>
python -c "import json;json.load(open('<file>',encoding='utf-8'));print('JSON OK')"
```

### 2. 关键值重读

**数字 / 路径 / 版本号 / 端口 / 文件名** 一律重新取，不用记忆。
写进交付物的每个数字，都要能指到「哪条命令输出的」。

### 3. 引用必带路径

- 说「已生成」→ 给**绝对路径**。
- 说「已修复」→ 给**回读到的内容**或**命令输出**。
- 说「线上是最新的」→ 给 **md5 对比结果**。

### 4. 自我反证（最重要）

交付前构造一个**「如果我没做对，这个检查会失败」**的验证。

| 类型 | 反证方法 |
|---|---|
| 代码 | 跑真实命令，贴完整输出（不是「跑通了」） |
| 网页 | 打开看渲染，或比截图，或检查关键 DOM 存在 |
| 数据 | 比条数、比 md5、抽 3 行核对 |
| 部署 | 拉线上文件与本地比 md5（**只看 HTTP 200 不算验证**） |
| 推送 | 比远端 HEAD 与本地 HEAD、比 tree sha（不靠「我刚推过」） |
| 配置 | 故意写个错值，确认检查会**变红**，再改回 |

> **反证变不红 = 你的检查是假的。** 这种情况比没检查更危险。

### 5. 虚假通过的三类信号

- 检查全绿但功能明显不对 → 检查覆盖不到真实路径
- 测试跑得特别快 → 可能全被跳过
- 只测了 happy path → 缺少失败路径断言

## 三、领域专属验收口径

### 前端 / UI

- 不只看「能打开」，要看**目标断点**（如 1440 / 1280 / 900 / 680 / 390 五档）。
- 视觉改动：给**改前改后对比**，不是描述「变得更好看了」。
- 交互改动：说清点了什么、出现什么。

### 数据 / 抓取

- 条数、字段完整率、去重后条数，三个数都要给。
- 抽样 3 条人工可核对的原文。
- 失败率与失败原因分类（不要只说「大部分成功」）。

### 部署 / 发布

```bash
# 唯一可信的「线上=本地」判据
md5sum <本地文件>
curl -s <线上URL> | md5sum      # 两者必须相同
```

### Git / 推送

```bash
git rev-parse HEAD                                  # 本地
gh api repos/<owner>/<repo>/git/ref/heads/<branch> --jq '.object.sha'   # 远端
# 两者必须相同，才算「推上去了」
```

## 四、五项汇报（S6 固定输出）

| # | 项 | 要求 |
|---|---|---|
| ① | **做了什么** | 一两句，动词开头 |
| ② | **分享链接** | 线上可访问 URL 原文（不加工、不缩短成描述） |
| ③ | **项目文件夹** | 本地绝对路径 |
| ④ | **是否推送远端** | 已推送/未推送 + 仓库 + 分支 + commit |
| ⑤ | **有无更新日志** | `README` / `CHANGELOG` 是否含本版块 |

**铁律**：

- 禁止用形容词代替数字。写「已优化性能」不算，写「首屏 2.8s → 1.1s」才算。
- 全部字段**实测**，不接受「我记得」「应该」。
- 第 ② 项给的是**能直接点开的 URL**，不是「已上线」三个字。

## 五、触发即停的红旗

出现下列任一，**停下来说明，不许继续编**：

- 要引用的文件 / 路径**还没读过**
- 关键数字来自记忆，而非工具输出
- 用户没确认就打算写文件 / 删文件
- 影响面说不清（不知道会动到哪些文件）
- 阶段门禁没过，却想直接跳下一阶段
- 推荐的能力/技能**没验证是否存在**

---

## 六、一句话总结

> **能被证伪的结论才叫结论。**
> 交付时你应该能回答：「如果这件事我搞砸了，哪个检查会亮红灯？」—— 答不上来，就别交付。
