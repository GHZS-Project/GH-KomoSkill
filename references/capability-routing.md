# 能力路由（通用版）

> 本技能只管**流程**，不管**用什么工具**。但流程推进中一定会遇到「这步该用什么能力」。
> 本文件给一套**与具体 agent 无关**的路由规则，以及**能力存在性验证**的硬要求。

---

## 一、路由三原则

| # | 原则 | 说明 |
|---|---|---|
| 1 | **最具体的优先** | 有专门技能就不用通用技能；有原生工具就不引第三方库 |
| 2 | **不重复实现** | 已装能力覆盖的功能，**绝不手写** |
| 3 | **先验证再用** | 推荐能力前必须先确认它**真实存在**，不存在就明示降级 |

---

## 二、能力存在性验证（防「虚报已调用」）

这是最容易产生幻觉的地方：**说了个不存在的技能名，然后当成用了**。

### 规则

```
推荐能力 → 验证存在 → 存在：可直接用
                    → 不存在：说「用内联能力替代」，禁止说「已调用」
```

### 通用验证方式

```bash
# 1) 目标 agent 的 skills 目录（按实际路径替换）
ls ~/.workbuddy/skills/ | grep -i "<关键词>"
ls ~/.codex/skills/    | grep -i "<关键词>"

# 2) 技能真实 id 看 frontmatter 的 name，不是目录名
grep -m1 '^name:' ~/.workbuddy/skills/<目录>/SKILL.md

# 3) 包管理器类能力
command -v <binary>        # 有输出即可用
python -c "import <mod>"   # 能 import 即可用
node -e "require('<pkg>')" # 能 require 即可用
```

> **注意**：目录名 ≠ 技能 id。常见情况是目录 `react-best-practices` 而 `name: vercel-react-best-practices`。
> 按名字路由时会匹配不上 —— 这就是「明明装了却说没有」的根因。

## 三、能力分类决策树

```
需求进来
  │
  ├─ 是「一次性单一能力」任务？（改个表、生成个文档、查个数据）
  │     └─ 直接路由到对应能力，不走六阶段
  │
  └─ 是「需要多阶段推进的小项目」？（做工具、建站、写系统）
        └─ 走 S0→S6 流程；流程内每步再路由具体能力
```

### 常见类别 → 能力类型（与具体产品无关）

| 需求类别 | 该找什么能力 |
|---|---|
| 文档 / 表格 / 演示 | 办公文档类技能；**新建**与**改既有**通常是两个不同技能 |
| PDF | PDF 处理类（读写 / 合并 / OCR 可能分开） |
| 网页自动化 / 截图 | 浏览器驱动类；优先无头浏览器 |
| 图片处理 | 图像处理类（去水印 / 抠图 / 增强） |
| 图片/视频生成 | 多模态生成类 |
| 数据清洗 / 透视 | 表格分析类 |
| 后端 / 数据库 / 登录 | 云服务 / BaaS 类 |
| 部署上线 | 静态站点 / 服务托管类 |
| 前端开发 | 前端框架 + 设计 + 性能（常需组合多项） |
| 爬取 / 抓页面 | 抓取类；需要绕过动态渲染时叠加浏览器类 |
| Git / 仓库 | Git 操作类（含 CI、PR、Issue） |

## 四、组合路由

一句话命中多个类别时：**取并集 + 去重**，指定一个主流程，其余辅助。

例：「把这份 CSV 做成 PPT 周报」
- 主流程：PPT 类
- 辅助：表格类（先提取/汇总数据）
- 顺序不能反 —— 先出数，再出稿。

**冲突处理**：两个能力都能做同一件事时，选**更窄**的那个（更窄 = 副作用更小）。

---

## 五、降级与替代

能力不存在时，**必须显式说明**，三选一：

| 方案 | 何时用 | 怎么说 |
|---|---|---|
| **内联实现** | 功能简单，几十行能搞定 | 「没有现成技能，我用内联代码实现，逻辑是…」 |
| **换等价能力** | 有同类能力可用 | 「A 不存在，改用 B，差异是…」 |
| **装能力** | 该功能复杂且会复用 | 「建议装 X，装之前先说明它会带来什么依赖」 |

**禁止**：假装调用了不存在的技能；把「我手写的」说成「用技能做的」。

---

## 六、路由的边界

- 路由层只管**选能力**，不管**推进阶段** —— 阶段推进永远是本技能（流程层）的事。
- 路由层**不许**自行改动用户的项目文件。
- 多条路径都可行时，给用户**一句话选择**，不要长篇对比。

---

## 七、一句话总结

> **说「已调用」，就必须能指出它装在哪。** 指不出来，就是没调用。
