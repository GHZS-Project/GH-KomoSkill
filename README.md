# GH-KomoSkill

> 📚 **本文档属于 GH 系列交接项目。** 总入口（全部 10 个仓库索引、可用性实测、可复制的 AI Agent prompt）：https://github.com/A13612812330/GH-Handover

**一个可以 clone 下来直接用的「AI 协作工作法」技能。**

不管你用 Codex、WorkBuddy 还是 Claude，装上它，agent 的行为会从「你说一句它干一段」变成：
**先问清 → 先出单子 → 先过门禁 → 干完自己反证 → 给你五项实测汇报。**

> 它不替你写代码。它管**怎么把一件事做完并且可交付**。

---

## 为什么会有这个东西

用 agent 久了，反复被同一个问题咬：

| 痛点 | 典型场面 |
|---|---|
| **它要求你写长 Prompt** | 「请详细描述需求背景、预期输出、技术偏好…」——我只想做个记账网页 |
| **它假装已经做完** | 「已修复 ✅」，打开一看文件根本没变 |
| **它换个会话就失忆** | 新开会话又从头问一遍「你想做什么项目？」 |

三个痛点对应三种真实缺失：

1. **缺流程** —— 没有阶段概念，边问边做，需求一变就返工。
2. **缺证据纪律** —— 模型不是不老实，是没人要求它「说完成必须给东西」。
3. **缺留档** —— 上下文在会话里，会话结束就没了。

本技能就是补这三样。**全部落在可执行的脚本和可校验的门禁上，不是一堆「请务必」的劝告。**

## 六阶段

```
S0 进场判断      判类型（新建/续作/修补/调研）· 判风险 · 判步数        不打扰你
      ↓
S1 需求补全      4 要素缺哪问哪（一次一问）→ 需求确认单               你回「确认」
      ↓
S2 启动确认      8 项清单 → ⛔ 本阶段禁止建文件 / 装依赖 / 改配置        你回「确认」
      ↓
S3 执行计划      ≤5 大步，每步四属性（做什么/动什么/怎么验/风险）     你回「确认」
      ↓
S4 分步执行      逐步做 + 每步给产物路径 + 阶段小结 + 大输出落盘
      ↓
S5 验收交付      交付验收单 + 自我反证（构造能证伪自己的检查）         你回「通过」
      ↓
S6 归档收尾      问是否推远端 → 写留档 → 五项汇报（全部实测）
```

**门禁是硬的**，不是提示：`flow_state.py --gate` 退出码非 0 就不许往下走。

## 它改变什么

| 场景 | 没有它 | 有它 |
|---|---|---|
| 你提需求 | 被要求写完整 Prompt | 说「做个工具」就启动，它问一个关键问题 |
| 信息不全 | 它猜着做，做完才发现猜错 | 一次问一项，补齐才动手 |
| 需求变更 | 已建一堆文件，边改边乱 | S2 禁止落盘，改需求零成本 |
| 它说完成了 | 「已完成 ✅」（无法验证） | 给绝对路径 + 回读内容 + 命令输出 |
| 交付质量 | 只测 happy path | 必须做一次「能证伪自己」的检查 |
| 换会话 | 从头问一遍 | 一条命令读回 22 行简报 |
| 收尾 | 「搞定了」 | 五项汇报，每个字段实测 |

完整实例见 **[`examples/01-一句话到交付.md`](examples/01-一句话到交付.md)** —— 一次 6 个字的请求，到五项汇报的全过程。

## 极简指令

说一个词就行：

| 你说 | 它做什么 |
|---|---|
| `确认` / `对` / `ok` | 通过当前节点，进下一阶段 |
| `继续` / `下一步` | 先召回上下文，再往下做 |
| `停` / `等等` | 立即终止，保留已完成部分，报停在哪一步 |
| `改：XXX` | 只改 XXX，其它不动，改完回读 |
| `重设：XXX` | 重置核心需求，回 S1 重出确认单 |
| `整理下状态` | 进度 + 产物路径 + 下一步 |
| `跳过` | 跳过当前阶段（仅低风险可跳） |

有歧义时默认按「继续当前项目」理解，不会莫名其妙重走 S1。

## 核心设计：四条不妥协

### 1. 门禁写进代码，不写进提示词

劝告「请务必确认后再执行」是没用的。`flow_state.py --gate` 返回 `2` 就是没过，
agent 没法绕过 —— 这是**机制**，不是**自觉**。

### 2. 完成必须有物证

`references/evidence-discipline.md` 定了三态标注（事实 / 推断 / 待核验），
以及「改完回读」「关键值重读」「自我反证」。

其中**自我反证**是分水岭：交付前必须构造一个「如果我没做对，这个检查会失败」的验证。
**反证变不红 = 检查是假的。**

### 3. 单一事实来源

长期约定只写 `PROJECT.md`，日志只写「今天干了什么」。
**两处都写 = 迟早打架。** 压缩时数字/路径/命令/报错原文/决策理由一条都不许压。

### 4. 交付形态固定

不管项目多小，收尾都给五项：做了什么 / 分享链接 / 项目文件夹 / 是否推远端 / 有无更新日志。
**禁止用形容词代替数字。**

## 脚本

```bash
# 项目状态机
python scripts/flow_state.py <项目目录> --init --name 项目名
python scripts/flow_state.py <项目目录>                      # 看进度
python scripts/flow_state.py <项目目录> --set S3             # 推阶段
python scripts/flow_state.py <项目目录> --ok S1 交付产物      # 勾要素
python scripts/flow_state.py <项目目录> --gate S2            # 校验门禁（0 通过 / 2 未过 / 3 未初始化）

# 防失忆简报
python scripts/project_brief.py <项目目录>
python scripts/project_brief.py --init <项目目录>
python scripts/project_brief.py --check <项目目录>
```

所有脚本只依赖 Python 标准库，**无第三方依赖**，Windows / macOS / Linux 通用。

## 适用 / 不适用

**适用**

- 小工具、脚本、单页网页、小程序、自动化流程
- 需要「做完能验收」的一次性交付
- 多轮修改、容易跑偏的项目
- 想让 agent 行为稳定可预期（不想每次重新调教）

**不适用**

- 纯问答、查资料（直接问更快）
- 一次改一个文件就跑的微任务（流程开销 > 收益）
- 企业合规要求下的正式审批流（这里没有审批系统）
